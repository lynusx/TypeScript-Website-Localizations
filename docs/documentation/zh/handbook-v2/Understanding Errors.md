# 理解错误信息

每当 TypeScript 发现错误时，它都会尽可能详细地解释出了什么问题。由于其类型系统是结构化的，这通常意味着它会提供较长的描述，以指出发现问题的位置。

## 术语

在错误信息中，你会经常看到一些术语，理解它们会对你很有帮助。

#### _可赋值给_（assignable to）

如果一个类型可以替代另一个类型，TypeScript 就认为该类型 _可赋值给_ 另一个类型。换句话说，`Cat` _可赋值给_ `Animal`，因为 `Cat` 是 `Animal` 可接受的替代品。

顾名思义，此关系通过检查 `t` 和 `s` 的类型来验证赋值 `t = s;` 是否合法。它还用于检查两个类型发生交互的绝大多数其他场景。例如，在调用函数时，每个实参的类型都必须 _可赋值给_ 参数声明的类型。

通俗地说，如果你看到 `T is not assignable to S`，可以把它理解为 TypeScript 在说"_`T` 和 `S` 不兼容_"。但请注意，这是一种 _单向_ 关系：`S` 可赋值给 `T` 并不意味着 `T` 可赋值给 `S`。

## 示例

让我们来看一些错误信息的示例，了解具体发生了什么。

### 错误详述

每个错误都以一条主信息开头，有时其后会跟有更多子信息。你可以把每条子信息看作是在回答其上一条信息的“为什么？”。让我们通过一些示例，看看它们在实际中是如何运作的。

下面的示例产生的错误信息比示例代码本身还要长：

```ts twoslash
// @errors: 2322
let a: { m: number[] }
let b = { m: [''] }
a = b
```

TypeScript 在检查最后一行时发现了错误。它报告错误的逻辑与判断该赋值是否合法的逻辑一致：

1. `b` 的类型可赋值给 `a` 吗？不能。为什么？
2. 因为 `m` 属性的类型不兼容。为什么？
3. 因为 `b` 的 `m` 属性（`string[]`）不可赋值给 `a` 的 `m` 属性（`number[]`）。为什么？
4. 因为一个数组的元素类型 (string) 不可赋值给另一个数组的元素类型 (number)。

### 多余属性

```ts twoslash
// @errors: 2322
type A = { m: number }
const a: A = { m: 10, n: '' }
```

### 联合类型赋值

```ts twoslash
// @errors: 2322
type Thing = 'none' | { name: string }

const a: Thing = { name: 0 }
```
